# Shared Conda Environment + Jupyter Kernel (U-M Great Lakes)

Build one conda environment on a shared Turbo (NFS) directory. The instructor/PI
can update it; students get **read-only** access and use it as a Jupyter kernel.

## Files

| File | Who | Purpose |
|---|---|---|
| `env.conf` | instructor | Course name, kernel name, shared path, mamba module. **The only file you normally edit.** |
| `environment.yml` | instructor | Packages (conda-forge). |
| `classenv.sh` | instructor | `setup`, `check`, `cleanup`. |
| `join.sh` | students | Generated by `setup` into the shared directory. Students never need this repo. |

Everything for one course lives in one directory (`SHARE_DIR`):

```
SHARE_DIR/
  env/                      conda environment (read-only for students)
  kernels/share/jupyter/kernels/<KERNEL_NAME>/   shared kernelspec
  join.sh                   one-command student setup
  environment.exported.yml  record of exactly what was installed
  .pkgs/                    package cache (safe to delete after setup)
```

## Instructor quick start

```bash
# 1. Edit env.conf (names + SHARE_DIR) and environment.yml (packages)
# 2. From a Great Lakes login node:
./classenv.sh setup          # create/update env, kernel, join.sh, permissions
./classenv.sh check          # verify
```

Then tell students **one command**:

```bash
bash /nfs/turbo/<lab>/<you>/<course>/join.sh
```

### Updating packages mid-term
Edit `environment.yml`, then `./classenv.sh setup`. Pip-installed packages and
removed packages are not cleanly handled by an in-place update; if anything looks
off, use `./classenv.sh setup --rebuild` (deletes and recreates the env).
Avoid updating while students are running notebooks: it can break live kernels.

### Next semester / next year (recommended)
Don't reuse last year's environment. Copy `env.conf`, change `KERNEL_NAME`,
`DISPLAY_NAME` and `SHARE_DIR` (e.g. `climate588-2026`), run `setup`, and send
students the new `join.sh` path. Old and new kernels coexist, so nothing breaks
for anyone still on the old one. Run `cleanup` on the old one when finished.

### End of term
```bash
./classenv.sh cleanup        # asks you to type the kernel name to confirm
```

## Student quick start

```bash
bash /nfs/turbo/<lab>/<you>/<course>/join.sh          # once
bash /nfs/turbo/<lab>/<you>/<course>/join.sh --check  # if something is wrong
bash /nfs/turbo/<lab>/<you>/<course>/join.sh --leave  # remove it later
```
Restart Jupyter / Open OnDemand; pick the course kernel from the kernel menu.
Extra packages: `%pip install --user <pkg>` in a notebook, or make a personal
conda environment. Note `--user` packages are shared with your other Python 3.12
environments, so a personal environment is cleaner for anything big.

## Permissions model

- Instructor owns everything and can write.
- Group and others: nothing writable. Group read/execute only; others none.
- `SHARE_GROUP` in `env.conf` (optional) sets the group that can read.
- Every parent directory above `SHARE_DIR` must be traversable (execute bit) by
  students; `setup` and `check` warn if not.

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| `Could not load module 'mamba...'` | Module names change after cluster software updates. `module spider mamba`, update `MAMBA_MODULE` in `env.conf`. |
| Conda complains about terms of service / `defaults` channel | Make sure `environment.yml` uses `conda-forge` + `nodefaults` only. |
| `Disk quota exceeded` during setup | Package cache fills your home. `setup` already redirects it to `SHARE_DIR/.pkgs`; check Turbo quota too. |
| Student: kernel not in the list | `bash join.sh --check`. Usually a missing link or the student isn't in the Turbo group. |
| Student: `Permission denied` | Parent directory missing execute bit, or student not in the group. Run `./classenv.sh check`. |
| Kernel starts then dies / geo libraries say "PROJ/GDAL data not found" | Re-run `setup` (it writes `GDAL_DATA`/`PROJ_DATA` into the kernelspec). |
| Kernel shows in list but fails after `cleanup` | Stale link. `bash join.sh --leave` (or `rm ~/.local/share/jupyter/kernels/<KERNEL_NAME>`). |
| `rm: ... Stale file handle` / odd NFS errors | Transient Turbo issue; retry, then contact ARC support. |

## What changed from the old version

- One script with subcommands; all paths derived in one place (the old cleanup
  script looked in a different kernel directory than setup created).
- Scripts no longer depend on the current directory.
- No `conda activate` under `set -u` (it breaks); the env's python is called directly.
- Kernelspec is updated in place (no window where the kernel doesn't exist) and
  carries `PATH`, `GDAL_DATA` and `PROJ_DATA`.
- conda-forge only; redundant pins removed; `dask`/`plotly` moved from pip to conda.
- Student script is generated with baked-in values, handles stale links, and has `--check`.
- Permissions use `u+rwX,g+rX,o-rwx` (files are no longer all marked executable).
- Cleanup requires typing the kernel name and only deletes known subdirectories.
